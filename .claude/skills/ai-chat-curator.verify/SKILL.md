# 사실 교차 확인 — 공식 출처로, 지금 기준으로

이 방의 사람들은 문안을 믿고 업무에 쓴다. 틀린 소식 하나가 "이 방 정보는 믿을 만하다"는 신뢰를 깎으므로, 확인이 안 되면 확인이 안 됐다고 분명히 남긴다.

## 1. 대상

프롬프트가 준 후보 ID 가운데 `needs_verification: true`인 후보는 모두 확인한다. 그 밖의 후보도 기능에 관한 주장이 있으면 확인한다.

## 2. 확인 순서

후보의 `claims`를 하나씩 다음 순서로 확인한다.
1. **해당 회사의 공식 출처**: 블로그·릴리스 노트·도움말 센터·요금 페이지·공식 계정 공지. 출처 목록은 `../ai-chat-curator.collect/references/sources.md`의 「a. 공식 발표」
2. **신뢰할 수 있는 매체**: 공식 출처에 아직 없을 때, 회사 관계자 확인이나 직접 시연이 담긴 주요 IT 매체 보도
3. **반대 근거 찾기**: 주장을 부정하거나 수정한 글(정정 공지, 롤백, 출시 연기)을 따로 검색한다. "~ 철회", "~ rollback", "~ delayed", "~ 정정"

근거는 직접 연 페이지에서만 가져온다. 페이지의 작성일·갱신일을 적는다.

## 3. 판정

| 상태 | 기준 |
| --- | --- |
| 확인됨 | 공식 출처가 주장 전체를 뒷받침하고, 이후 철회·수정이 없다 |
| 부분 확인 | 공식 출처가 일부만 뒷받침한다(예: 미국만 출시, 유료 요금제만, 순차 적용). 또는 공식 출처는 없고 신뢰할 수 있는 매체 보도만 있다 |
| 아직 공식 확인 안 됨 | 공식 출처도, 신뢰할 매체 확인도 없다. 커뮤니티 이야기만 있다 |
| 사실 아님 | 공식 출처가 주장과 반대되는 내용을 밝혔다 |
| 철회·변경됨 | 한때 맞았지만 이후 철회·수정·연기됐다. `corrected_claim`에 지금 기준 내용을 쓴다 |

- 커뮤니티 출발 후보(`community_origin: true`)는 공식 출처 없이는 `확인됨`을 주지 않는다
- 한국에서의 적용 여부, 요금제별 차이, 웹·앱 차이는 `caveats`에 적는다. 문안에서 빠지면 오해가 생기는 조건이다
- `freshness_ok`: 근거 작성일이 기간 안이거나, 기간 밖이라도 지금 유효함을 확인했으면 참

## 4. 저장과 응답

프롬프트가 준 경로(`03_fact-checker_{n}.json`)에 쓴다. 형식은 `../ai-chat-curator/references/data-schema.md`의 「교차 확인 결과」. 응답은 상태별 건수와 경로만 짧게 한다.
