# 문안 검증 — 9항목, 하나라도 빠지면 반려

검증자는 고치지 않고 판정만 한다. 반려할 때는 작성자가 바로 고칠 수 있게 **어느 줄이 왜 문제이고 어떻게 바꾸면 되는지**를 적는다.

## 1. 읽기

- `{실행 폴더}/04_writer_drafts.md`, `04_writer_candidates.md`
- `02_curator_candidates.json`, `03_fact-checker_*.json`, `00_main_options.json`
- 이전 회차 판정(`05_reviewer_round{r-1}.json`)이 있으면, 지난번 반려 사유가 해결됐는지부터 본다

## 2. 기계 점검

```bash
python -I .claude/skills/ai-chat-curator/scripts/curator.py check-drafts "{실행 폴더}/04_writer_drafts.md"
```
스크립트가 잡은 문제는 `형식`(분량·줄·링크·이모지), `표현`(과장), `중복`(posted.md) 항목의 반려 사유가 된다. 스크립트 결과만으로 통과시키지 않는다 — 스크립트는 셀 수 있는 것만 센다.

## 3. 문안별 체크리스트

| 항목 | 통과 조건 | 확인 방법 |
| --- | --- | --- |
| 사실 확인 | 소식·팩트체크 문안의 사실 문장이 교차 확인 결과와 일치한다. 상태가 `아직 공식 확인 안 됨`이면 문안에 그 표현이 있다. `caveats`의 조건(지역·요금제)이 빠지지 않았다 | 문안 문장 ↔ `03_fact-checker` 근거 대조 |
| 최신성 | 근거 작성일이 기간 안이거나 지금도 유효하다. 철회·변경된 내용을 옛 기준으로 쓰지 않았다 | `freshness_ok`, `corrected_claim` |
| 저작권 | 원문 문장을 그대로(또는 거의 그대로) 옮기지 않았다. 인용은 한 문장 이내이고 출처가 있다 | 원문을 WebFetch로 열어 대조. 못 열면 `notes`에 적음 |
| 개인정보 | 커뮤니티 작성자의 닉네임·실명·회사명, 캡처 속 정보가 없다 | 문안·후보 문서 전체 |
| 광고 배제 | 원문 링크가 유료 강의·제휴 링크·상품 판매 글이 아니다 | 링크 주소(제휴 파라미터)와 원문 내용 |
| 공정성 | 문안이 특정 도구를 띄우거나 깎지 않는다 | 평가 표현 |
| 안전 | 회사 기밀·개인정보를 AI에 넣으라고 권하지 않는다. 실제 자료를 다루는 팁에 "민감한 내용은 지우고" 같은 조건이 있다 | 팁·지시문 예시 |
| 표현 | 과장 없이, 직장인이 바로 이해할 말투다. 첫 줄에 핵심이 있다. 풀지 않은 전문 용어가 없다 | 첫 줄, 용어 |
| 중복 | posted.md와 같은 링크·같은 내용이 아니고, 이번 실행 문안끼리도 겹치지 않는다 | 스크립트 + `posted-list` |
| 형식 | 본문 300자·3~5줄 이내, 마지막 줄 원문 링크, 이모지 0~2개, 질문거리는 질문으로 끝남 | 스크립트 |

하나라도 미충족이면 `verdict: "반려"`, `failed`에 항목 이름, `reasons`에 문제 줄과 이유, `fix_hint`에 고칠 방향을 적는다.

## 4. 실행 전체 판정 (`run_level`)

- **공정성**: 문안 전체의 도구 분포. 실행 옵션에 도구 초점이 없는데 한 도구가 문안의 절반을 넘거나, 세 도구 가운데 하나가 후보 목록에 한 건도 없으면 반려. 도구 초점이 있으면 "사용자 지정으로 예외"
- **후보 목록 문서**: 표 열(제목·유형·관련 도구·출처 링크·출처 유형·작성일·업무 관련도·검증 상태·추천 여부와 이유)이 모두 있고, 후보 수가 10개 내외이며, 문서에도 개인정보·광고 링크가 없다
- 실행 전체가 반려면 작성자가 문안을 바꾸거나 다음 순위 후보로 교체해야 한다. 어느 문안을 바꾸면 해결되는지 `fairness_note`에 적는다
