# 자동 실행 모드 — 매일 오전 10시(KST) 클라우드 예약 실행

Claude Code 클라우드 예약 실행(routine)이 이 저장소를 받아 "ai-chat-curator 자동 실행"으로 부른다. 지켜보는 사람이 없으므로 **아무것도 묻지 않고 끝까지 간다.** `AskUserQuestion`을 쓰지 않고 응답을 기다리지 않는다. 결과는 사용자 본인 카카오톡(나에게 보내기)과 저장소 커밋으로만 남긴다.

오픈채팅방에는 보내지 않는다. 카카오는 오픈채팅방 게시 API를 열어 두지 않았고, 비공식 봇은 운영정책 위반이라 방장 계정이 막힐 수 있다. 사람이 받은 메시지를 방에 전달한다.

## 왜 기준이 수동 실행보다 엄격한가

수동 실행에서는 사람이 문안을 보고 거른다. 자동 실행에서는 그 단계가 사라지므로, 사람이 안 봐도 틀릴 일이 거의 없는 것만 보낸다. 2026-11-23 실행에서 교차 확인이 "확인됨"이라 판정한 문안에도 원문과 다른 문장이 있었고, 검증 3회차에서야 통과했다. 그래서 한 번이라도 사실 확인으로 반려된 문안은 고쳐졌어도 보내지 않는다.

## 발송 자격 (`curator.py auto-pick`이 판정)

| 유형 | 자격 |
| --- | --- |
| 소식 · 팩트체크 · 주의할 점 | 교차 확인 `확인됨` + 근거에 `공식` 출처 + 마지막 검증 통과 |
| 업무 팁 | 검증 1회차부터 반려 없이 통과 |
| 질문거리 | 보내지 않음 |
| 모든 유형 공통 | 검증 중 `사실 확인`으로 반려된 적이 있으면 제외. 교차 확인 `사실 아님`·`철회·변경됨`이면 제외 |

자격 있는 문안 가운데 번호가 가장 앞선 것 하나만 보낸다(작성자가 추천 순으로 번호를 매긴다). 판정은 스크립트가 한다. 메인이 기준을 넓혀 고르지 않는다.

## 절차

본 절차(SKILL.md)의 0~7단계를 따르되 아래만 다르다.

**A0. 토큰 확인** — `python -I .claude/skills/ai-chat-curator/scripts/kakao.py token-status`. `warn`이 참이면 기억해 두었다가 A6에서 경고를 함께 보낸다. 토큰 문제로 실행을 멈추지 않는다(전송만 실패할 뿐 산출물은 남긴다).

**0단계 차이**
- 스펙은 달마다 하나: `NNN-auto-YYYYMM`. 이번 달 스펙이 이미 있으면 그 실행 로그에 그날 줄을 이어 쓴다. 없으면 In Progress로 새로 연다. 달의 마지막 실행 또는 다음 달 첫 실행에서 지난달 스펙을 완료 기록과 함께 Done으로 닫는다
- `00_main_options.json`에 `"mode": "auto"`를 넣는다

**1단계 차이** — 옵션은 기본값(최근 7일, 문안 3~5, 초점 없음, 관점 a·b·c·d). 게시 기록은 최근 90일. 반응 기록은 `inputs/feedback.md`.

**2~6단계** — 같다. 검증은 최대 3회차. 공정성 반려는 수동과 같이 처리한다(하루 한 건만 보내지만 후보 문서의 균형은 유지한다).

**A4. 고르기** — `python -I .claude/skills/ai-chat-curator/scripts/curator.py auto-pick {RUN}` → `pick`(번호 또는 null). 결과를 `RUN/06_main_autopick.json`에 저장한다.

**A5. 저장** — 7단계처럼 `OUT`에 복사한다. 게시 기록에는 **보낸 한 건만** `제안`으로 넣는다(`--only {pick}`). 고르지 못했으면 아무것도 넣지 않는다.

**A6. 보내기**
- 고른 문안이 있으면: `kakao.py send-draft {RUN}/04_writer_drafts.md --no {pick}` — 본문은 200자 단위로 줄 경계에서 나뉘고, 원문 링크가 마지막 한 통으로 따로 간다
- 없으면: `kakao.py send-text "[글감 봇] 오늘은 기준을 넘는 글감이 없어 쉽니다. 후보 {N}건 중 공식 확인·검증 통과 문안 없음({대표 사유})."`
- A0에서 `warn`이었거나 전송 결과에 `refresh_rotated: true`가 있으면 `token-status`의 `message`(또는 "토큰이 갱신되어 내일부터 전송이 멈출 수 있어요. 오늘 재발급해 주세요.")를 `send-text`로 한 통 더 보낸다
- 전송 실패(`ok: false`)는 다시 시도하지 않는다(인증·네트워크 문제는 다시 해도 같다). `RUN/99_main_failure.md`에 오류를 적는다

**A7. 마감과 커밋**
- 이번 달 스펙 실행 로그에 한 줄: `{날짜} | 자동 실행 | 후보 N, 문안 K, 발송 {번호·제목 | 쉼} , 전송 {성공|실패: 사유}`
- `git add -A && git commit -m "auto: {날짜} 글감 {발송|쉼}" && git push`. push가 거부되면 `99_main_failure.md`에 적고 끝낸다(다음 실행이 같은 글을 다시 낼 수 있으므로 보고서에 남긴다)

## 실패 처리

| 상황 | 대응 |
| --- | --- |
| 웹 검색 한도·권한 거부로 수집이 대부분 비었다 | 다시 시도하지 않는다. 남은 관점으로 진행하고, 후보가 없으면 쉼 알림에 "수집 실패"를 적는다 |
| 검증 응답이 JSON이 아니다(재호출 후에도) | 그 회차 판정이 없으므로 `auto-pick`이 모두 자격 없음으로 본다 → 쉼 알림 |
| 카카오 환경 변수 없음·토큰 만료 | 산출물·커밋은 그대로. 전송 실패를 `99_main_failure.md`에 남긴다. 사용자는 카톡이 오지 않는 것으로 알게 되므로, 수동 세션에서 "자동 실행 결과 확인해줘"로 저장소를 보면 된다 |
| 연결 실패(네트워크) | 클라우드 환경의 네트워크 허용 목록에 `kauth.kakao.com`·`kapi.kakao.com`이 있는지 확인하라고 `99_main_failure.md`에 적는다 |

## 사람이 하는 일

- 받은 메시지를 길게 눌러 오픈채팅방으로 전달
- 올렸으면 수동 세션에서 "오늘 거 올렸어" → 게시 기록 `게시`로 갱신(저장소를 먼저 pull)
- 토큰 경고가 오면 PC에서 재발급: `kakao.py auth-url` → 로그인 → `kakao.py exchange {code}` → 클라우드 환경 비밀값 `KAKAO_REFRESH_TOKEN`·`KAKAO_TOKEN_ISSUED` 교체
